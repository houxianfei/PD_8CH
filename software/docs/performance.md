# UI 帧率分析与优化 — v1.2.3（性能基线）

日期：2026-11-19。Windows x64、VS2019 v142 Release、D3D11硬件设备、1280×850、八个独立子图、65536帧保留缓存、每图最近1500点。预热60帧后统计300帧；定时器测试各90帧。测试完全使用内部数据和离屏渲染，没有连接真实USB或控制桌面。

## 主要瓶颈

原代码每帧调用 `std::this_thread::sleep_until(本帧开始+16.67ms)`。本机实际等待平均 **30.884ms**，对应约 **32.38FPS**；界面实际处理平均仅 **1.060ms**。主要损耗来自普通Windows休眠的唤醒粒度及每帧重设截止时间，而不是八通道曲线计算耗尽16.67ms预算。

微软说明普通Sleep精度受计时器分辨率影响；高精度等待可使用Windows 10 1803起支持的 `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`：[Sleep文档](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-sleep)、[高精度计时器文档](https://learn.microsoft.com/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw)。

## 测量结果

| 阶段 | 优化前平均ms | 优化后平均ms |
|---|---:|---:|
| 采样缓存快照 | 0.321495 | 0.003375 |
| Main UI | 0.047035 | 0.038218 |
| 绘图数据准备 | 0.040253 | 0.026522 |
| 独立子图及文本 | 0.232081 | 0.188497 |
| 设置检查/保存 | 0.034246 | 0.005248 |
| D3D11离屏绘制提交 | 0.259414 | 0.175222 |
| 完整界面处理（不含等待） | 1.060096 | 0.459675 |

高精度定时器平均周期 **16.665476ms**（约 **60.004FPS**）。加入八通道界面工作的完整限帧测试，平均周期 **16.665364ms**（约 **60.005FPS**），P95为 **17.352ms**。固定平均帧率不意味着每一帧都严格等于16.67ms，操作系统调度会带来少量抖动。

优化后的静止界面还会复用已有校准数据，不再每帧重算。上表采用每帧数据版本变化的情况，覆盖连续采集时需要持续重建曲线数据的路径。

## 实现改动

- 使用高精度waitable timer和连续的绝对60Hz截止时间；处理超预算帧时丢弃过期节拍，避免积累漂移。没有忙等；旧系统使用有配对释放的计时器回退。
- 隐藏宿主窗口不再清屏、绘制或Present；只渲染两个可见窗口的swap chain。移除隐藏宿主 `Present(1)` 和软件限帧叠加的等待风险。
- UI快照只复制最近1500帧，隐藏曲线窗口时只读元数据；原先每帧复制整个65536帧缓存并持有SDK锁。缓存总数仍完整显示，点击CSV保存时按需获取全部保留帧。
- 复用绘图vector，在新数据或校准变化时计算Power和最小/最大值；未变化的数据直接复用。通道名称、曲线选择和P0/P1行为不变。
- 自动设置检查最多每100ms执行一次，避免每帧构造ini文本；修改后仍自动保存，关闭时强制保存。
- 新增分阶段计时，区分快照、Main UI、数据准备、绘图、设置、帧开始、绘制提交、窗口更新、每个可见窗口Present和限帧等待。没有修改第三方ImGui/ImPlot文件。

## 复现与现场定位

在project_0目录运行：

```powershell
./software/scripts/benchmark.ps1
```

原始CSV在 `build/performance_before/` 和 `build/performance_after/`；随文档附带本次基线和优化后的CSV。

实际桌面、多窗口和真实采集环境可使用同一程序的可选诊断启动参数：

```powershell
& '.\afs_8ch.exe' --profile
```

约预热1秒后采集600帧，后台写入程序旁 `cfg/ui_performance.csv`；默认启动不生成此文件。报告包含每阶段平均/P95/最大耗时。分析时关闭会阻塞主线程的文件对话框；Windows窗口移动、远程桌面、GPU竞争或调试版会影响结果。

本报告中的FPS由真实steady_clock耗时计算；不是截图中为绘图测试设置的ImGui DeltaTime。离屏硬件提交不等于GPU完成耗时，离屏测试没有真实可见窗口的DWM/Present等待，因此未据此声称所有实物和显示环境都已达到60FPS。现场Present耗时可由上述 --profile 报告确认。
