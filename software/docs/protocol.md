# PD 8CH 主机协议

固件依据当前 `project_0/rtl` 及 `sim/reference_vectors.vh`；参考 CRC 黄金向量源于 `afs_fireware` 的 `afs_v1 ae1a285`。既有采集协议和全部管脚保持，新增F4只读固件版本寄存器。

v1.0.0增加可通过公开SDK调用的Simulation传输。它模拟0x00～0x07 ADC读取、F0/F1/F2控制、F3状态及F4版本读取，按实时节拍生成双组八通道上传帧和CRC，复用以下解析及生命周期流程；不会访问USB或修改固件。SDK及界面演示见simulation.md。

## 采集设置

| GUI 选项 | F0 写入值 | 实际间隔 | 时间戳步长 |
|---|---:|---:|---:|
| 1 kHz | 49999 | 50000 个 50MHz 时钟 | 1ms |
| 100 Hz | 499999 | 500000 个 50MHz 时钟 | 10ms |
| 10 Hz | 4999999 | 5000000 个 50MHz 时钟 | 100ms |
| 1 Hz | 49999999 | 50000000 个 50MHz 时钟 | 1000ms |

`F0 = 50000000 / rate_hz - 1`，符合固件间隔计数“写入值加一”的规则。有限采集帧数 `F2 = ceil(duration_ms × rate_hz / 1000)`，第一帧立即产生、时间戳为 0，因此最后一帧时刻通常小于设置时长。1Hz 下时长小于 1 秒时只采集第一帧。

始终选择组0、组1。有限启动 `F1=0x301`，连续启动 `F1=0x303`；显示选择不会改变这两个组。启动前发停止和清 FIFO 请求，再排空主机残留数据并读取 F1 确认空闲。停止时写 `F1=0`，保留最后完整帧并排空到至少连续 50ms 无数据，再确认 F1 为零。排空上限为两秒。

## 命令、回复和上传

- 命令固定八字节：`AA CMD ADDR D0 D1 D2 D3 CRC`，CMD=1 写，CMD=2 读；32 位数据小端。读取的数据字段为零。
- CRC 初值0、多项式0x07，按每个64位字的 bit63→bit0 顺序计算，不能按线缆字节顺序调用普通 CRC8。
- 写命令无回复。读回复为32位小端数据重复两次。SDK 仅在上传停止并排空后读取寄存器；GUI 不直接接触 FTDI API。
- 上传头线缆顺序为 `00 CRC TS0 TS1 TS2 TS3 03 AA`，后接两组各8字节，总帧长24字节。
- 组0线缆顺序为 CH3、CH2、CH1、CH0，每通道低字节在前；组1为 CH7、CH6、CH5、CH4。应用还原为 CH0～CH7 的有符号16位值。
- 上传 CRC 先处理 CRC 字节置零的帧头，再累积两组数据。
- USB 读取可拆开或合并帧，解析器保留未满帧的字节。坏头或 CRC 错误按字节向后寻找下一候选头；CRC、丢弃字节和时间戳跳号计数在界面显示。
- 时间戳按32位计数，解析器扩展跨回绕时间；拒绝重复或倒退帧。跳号体现真实上传间隔，不压缩时间。`timestamp_ms = expanded_timestamp × (max(F0,1000)+1) / 50000`。

八通道曲线来自有效上传帧，表格可由上传帧或Get更新。连接后未获取数据时显示 `--`。空闲时 Get 从 0x00～0x07 顺序读取八个原始 ADC 寄存器，全部成功后一次更新表格；由于固件没有寄存器快照锁存命令，这八个读取值不保证来自同一次转换。采集中 Get 使用最近有效的完整帧，不发寄存器读取。Get 不写入曲线缓存。没有后台逐通道寄存器轮询，不会把无独立帧头的寄存器回复混入采样流。

## 状态和线程

USB 搜索、连接、寄存器访问、采集和断开统一由一个 SDK 线程执行。GUI 每帧获得有界缓存的稳定快照，CSV 写入使用独立任务。正常队列暂时为空不算失败；仅连续模式在两秒无有效样本时进入超时保护，此门限允许1Hz的正常帧间等待。有限模式使用目标帧数、时间戳及采集时长判断结束，不使用两秒无数据断开规则。空闲连接每100ms检查一次设备，拔线后关闭句柄。

有限模式达到目标有效帧数，或最后有效时间戳达到 `(目标帧数-1)×采样周期` 时结束；缺少末帧时，在启动后的设置时长加500ms且至少100ms无有效帧时停止并排空。缺帧或尾帧不完整时提示数据不足，保留连接及完整样本，不伪报完整采集。短命令写入不自动重发，提示复位 FPGA，以免继续使用失步的命令拼接器。

曲线显示最近1500帧；每图文本中的当前值取最新帧，最小/最大/PV取这1500帧中的该通道。取消某通道仅删除该子图。曲线和图内统计使用 P1×(P0+ADC) 的校准值，ADC 缓存本身不变。GUI CSV导出所选通道的名称、ADC和Power，并在文件头固定本次校准及采集元数据。CSV行使用主机启动命令UTC加FPGA相对时间计算的绝对UTC时间，显示至微秒；UI绘图内部仍用相对毫秒。Power使用double可往返的有效位数。SDK 原始九列 CSV 接口保持不变。

## 校准和名称配置

公共 `Calibration` 包含八组 P0/P1 和名称，默认0/1和CH0～CH7。V2配置使用 `PD8CH_CALIBRATION_V2` 头，每行是 `编号 P0 P1 "名称"`，支持引号转义和空格；只接受PD V2格式，拒绝AFS及V1文件。加载时验证全部八行后才替换当前设置。保存先写临时文件，再替换目标文件。异常输入、非有限数值及会溢出的系数均拒绝；名称最多95个UTF-8字节，不允许控制字符。UI 内部绘图标识始终按CH编号生成，重名不造成子图合并。

## UI ini

`cfg/pd_8ch.ini` 的 `[PD][UI]` 节保存业务参数、名称、P0/P1、路径，文件后面由ImGui保存窗口和表格布局节。读取验证成功后一次应用参数；写入临时文件后原子替换。关闭时强制保存。导入校准文件立即更新ini快照，不自动启动硬件。损坏ini自动备份为同目录.invalid.*文件后重建；备份失败时禁止覆盖原文件。

## 采集时间锚点

主机在F1启动写命令前记录UTC微秒数，成功后发布至Snapshot。停止、完成或异常时记录结束UTC；Get不会改变锚点，重启采集清空旧缓存并建立新锚点。UI轻量快照携带相同元数据，导出时重新获取完整缓存和导出快照UTC。USB和FPGA协议不变，时间解释与CSV格式详见csv_format.md。

## 固件版本

PD固件1.0.0新增只读0xF4（AXI地址0x400003D0），返回0x00010000，格式为{reserved,major,minor,patch}，每项8位。写入无效，复位不改变版本。查询命令/应答、SDK字段和显示策略见[命名与版本说明](https://github.com/houxianfei/PD_8CH/blob/main/doc/pd_rename.md)。该新增寄存器不改变既有采样帧及命令格式。
